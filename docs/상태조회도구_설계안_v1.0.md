# Project Black Titan — 상태 조회·무결성 도구 설계안 v1.0

작성 2026-09-14. 대상: `tools/bt_query.py`, `tools/bt_doctor.py` 신설.

---

## 0. 왜 만드는가 — 설계 전 실측

설계에 앞서 `05_문체_상태_인계`(18MB · 385개 파일)를 실측했고,
**진행 중인 데이터 손상 1건**을 확인했다.

### 발견: 복선추적기 SNAP-068~101 (34개) 페이로드 동결

```
069~101 페이로드 해시 동일성 (첫 주석줄 제외)
     34 3fb004d3  ← SNAP-068 ~ SNAP-101 전부 동일
      1 116d0d50  ← SNAP-102 (정상)
```

- 34개 파일이 **첫 줄 주석(`# … SNAP-0NN`)만 다르고 본문이 바이트 동일**하다.
- 전부 `as_of_episode: 67` · `last_updated_by: EP067 「표」 v1.0 …`으로 찍혀 있다.
- SNAP-142 헤더에 적힌 **2026-08-21 「2차 동결 복구」 기록은 실제로 복구되지
  않았다.** 주석 블록만 추가됐고 페이로드는 그대로다.
- 같은 파일의 재발 방지 메모 — `마감 시 as_of_episode 값이 해당 회차인지
  확인할 것` — 는 **사람의 눈에 맡겨져 있었고, 그래서 또 새어 나갔다.**

대조군: SNAP-*.yaml(본상태) 143개는 `through_chapter` 불일치 0건, 연속
바이트 동일 0건으로 **정상**이다. 손상은 복선추적기 계열에 한정된다.

> **이 도구의 1차 존재 이유는 조회가 아니라 이 부류의 조용한 실패를
> 기계가 잡게 만드는 것이다.** 조회는 그 위에 얹는다.

### 범위 경계 — `precheck.py`와 겹치지 않는다

| | 대상 | 답하는 질문 |
| --- | --- | --- |
| **기존** `tools/precheck.py` | `10_회차` 승인 **본문** | "이 말이 지면에 나온 적 있나" |
| **신설** `bt_query.py` | `05_문체_상태_인계` **상태층** | "지금 상태가 뭐고, 언제 그렇게 됐나" |

본문 그렙은 이미 해결돼 있다. 비어 있는 건 **상태층 5종을 가로지르는 조회**다.

| 소스 | 개수 | 현재 조회 방법 |
| --- | --- | --- |
| `SNAP-*.yaml` | 143 | 최신 1개 열어 눈으로 |
| `복선추적기_SNAP-*.yaml` | 142 | 최신 1개 열어 눈으로 |
| `인물등장장부_*.md` | 100 | 최신 1개 열어 눈으로 |
| `선례대장_v1.1.md` | 1 (291줄 · 9절) | 통독 |
| `소급정정_*.md` | 14 | 파일명 추측 |

공통 문제: **가로 질의가 불가능하다.** "단아 부상 상태가 언제 바뀌었나"를
알려면 143개를 손으로 비교해야 한다.

## 1. `bt_query.py` — 상태 조회

### 1-1. `--who <인물>` — 인물 현재 상태 집계

3개 소스를 한 화면에 합친다.

```
python tools/bt_query.py --who 단아
```

```
■ 도단아  (SNAP-142 기준 · EP142)
  [상태]   ← SNAP-142 characters.dana 블록 전개
  [등장]   최근 지면 EP143 · S15 간격 0 · 직전 공백 최대 3
           ← 인물등장장부 v2.37
  [화계]   영진에게 반말(교신 포함) / 수아→영진 존댓말
           ← 선례대장 §1-B, §1-C
  [주의]   check_voice.py 알려진 오탐 4건 중 해당 0건
```

- `--at N` 으로 과거 시점 조회(`SNAP-N` 사용).
- 인물 ID는 SNAP `characters:` 키(dana/sua/youngjin/lucy/…)와 한글명을
  매핑 테이블로 양방향 해석.

### 1-2. `--thread <키워드>` — 복선 조회

```
python tools/bt_query.py --thread 고래상어
```

```
■ WHALESHARK-COMMANDER  ★★★★★ 고래상어형 — 처음이자 마지막
  line KJ · secret_layer 1 · status SIMMERING
  planted_at   EP142        last_progressed  EP142
  next_window  7-5(겨울 말)
  허용  형태·재질·안 공격함까지
  금지  7-5 지휘개체 원형이라는 것 = 겨울까지 0. 재등장 예고 0
```

`allowed_reveal_now` / `prohibited_reveal_now`를 항상 같이 띄운다 —
복선 조회의 실수요는 "이번 화에 어디까지 써도 되나"이기 때문.

### 1-3. `--due [EP]` — 회수 기한 도래 복선 ★핵심

```
python tools/bt_query.py --due 143
```

`active:` 중 `next_window`가 지정 회차 이하인데 아직 안 닫힌 것만.
`next_window` 값은 `EP145` · `7-5(겨울 말)` · `상시` 세 형식이 섞여 있으므로
**`EP\d+` 패턴만 기한 판정하고, 서술형은 `[수동확인]`으로 분리 출력**한다.
파싱 실패를 조용히 통과시키지 않는 것이 이 도구의 설계 원칙이다.

### 1-4. `--history <점키>` — 가로 질의 ★가장 큰 이득

143개 스냅샷을 훑어 **값이 바뀐 회차만** 출력한다.

```
python tools/bt_query.py --history characters.dana.injury
```

```
EP061  "없음"
EP074  "왼손 손끝 감각 저하"        ← 변경
EP112  "신경 손상 — 출격 불가"      ← 변경
EP131  "재활 중 · 미는 것 여덟"     ← 변경
(143개 중 변경 4회)
```

지금은 손으로 143개를 비교해야 나오는 답이다. 이 서브커맨드 하나가
도구 전체 가치의 절반이다. `assets`·`inventory`·`living_conditions`·
`relations` 등 SNAP의 모든 최상위 키에 동일하게 동작한다.

### 1-5. `--rule <키워드>` — 선례·소급정정 전문 검색

선례대장 291줄 + 소급정정 14건을 한 번에. **적중한 절 제목을 같이 출력**한다
(선례대장은 §1-B 같은 절 단위로 인용되므로 줄번호만으로는 못 쓴다).

```
python tools/bt_query.py --rule 계단
→ 선례대장 §2. 장소·동선  / 소급정정_2026-08-20_계단-승강기_v1.0.md
```

### 1-6. `--gap [N]` — 장기 미등장 조연

등장장부 변경행을 파싱해 N회차 이상 지면에 없는 인물. 기본 N=12.
「조연 부채」 관리가 이미 장부에 수기로 들어가 있는데(`간격 50 회수` 등),
그 계산을 기계가 한다.

## 2. `bt_doctor.py` — 무결성 검사

webnovel-writer의 `projection_log`를 이 프로젝트 방식(전체 복사 버전닝)에
맞게 뒤집은 것. **쓰기를 로깅하는 대신, 사후에 불변식을 검증한다.**

| # | 검사 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 | **스탬프** — 파일명 회차 == `as_of_episode`/`through_chapter` | **FAIL** | 현재 34건 적발 |
| 2 | **동결** — 연속 스냅샷 페이로드 해시 동일(첫 주석줄 제외) | **FAIL** | 현재 34건 적발 |
| 3 | **커버리지** — 승인 회차마다 SNAP·복선·장부가 다 있나 | FAIL | 장부는 100/143로 성긴 것이 정상일 수 있어 WARN 가능 |
| 4 | **헤더 드리프트** — 제목줄 버전 vs 표 버전 vs 파일명 기준회차 | WARN | v2.37 파일이 제목 `v1.52` · 기준 `EP001~139` · 파일명 `EP142기준` |
| 5 | **복선 기한** — `next_window` 지난 `active` 항목 | WARN | §1-3과 동일 로직 재사용 |

검사 2가 검사 1의 상위 집합처럼 보이지만 아니다 — 스탬프만 고치고 본문은
안 고친 경우(2026-08-21에 실제로 일어난 일)를 잡으려면 둘 다 필요하다.

`--fix` 는 **넣지 않는다.** 동결 복구는 각 회차 Gate-E 근거를 봐야 하므로
기계가 채울 수 없다. 도구는 적발까지만 하고 복구는 사람이 승인한다.

## 3. 구현 메모

**파서** — PyYAML 6.0.3 설치 확인. 상태 파일 285개 전수 `safe_load` 통과
(fail 0). 볼드·★·백틱이 섞인 문자열도 문제없다. 정규식 라인 파서 불필요.

**인코딩** — 기존 스크립트 관례대로 `# -*- coding: utf-8 -*-` + 명시적
`encoding="utf-8"`. 한글 리터럴이 들어가므로 **생성은 편집 도구로 하고
bash heredoc은 쓰지 않는다**(과거 한글 깨짐 선례).

**성능** — 143개 × 30KB = 약 4MB. `--history`는 전량 파싱이 필요하므로
`tools/__pycache__` 옆에 `.bt_cache.json`(mtime+size 키)을 두어 2회차부터
스킵. 초회 파싱은 2초 내외로 예상되어 캐시는 후순위여도 무방하다.

**경로** — `precheck.py`와 동일하게 `__file__` 기준 2단계 상위를 ROOT로.

**출력** — 사람이 읽는 텍스트가 기본. `--json`을 붙여 스킬이 파이프로
받을 수 있게 한다.

## 5. 채택하지 않은 것

- **임베딩/RAG** — webnovel-writer의 `vectors.db`. 상태층은 키가 정해진
  구조화 데이터라 의미검색이 필요 없다. 키 경로 질의가 더 정확하고 싸다.
- **SQLite 인덱스** — 4MB에 인덱스 DB는 과설계. 동기화 실패라는 새 고장
  지점만 생긴다.
- **델타 체인 전환** — 전체 복사를 델타로 바꾸면 143개 재구성이 필요하고,
  마감 스크립트가 조용히 실패하는 현재 문제를 오히려 키운다.
  **전체 복사 유지 + 사후 검증**이 이 프로젝트에 맞다.
- **자동 수정(`--fix`)** — §2 참조.

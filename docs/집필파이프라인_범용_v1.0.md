# 장편 연재 집필 파이프라인 — 범용판 v1.0

블랙 타이탄에서 실제로 굴러가는 절차에서 **작품 고유값을 빼고 구조만 남긴** 문서다.
다른 작품에 쓸 때는 §10의 슬롯만 갈아 끼운다.

---

## 0. 파이프라인의 형태 — 두 방향의 흐름

```
        [설계 하향]                              [기억 상향]
   L0 바이블 · 레지스트리                     승인 본문
        ↓                                        ↓
   L1 전체 플롯                              회차 델타(변한 것만)
        ↓                                        ↓
   L2 대단위(부·계절)                        상태 스냅샷 교체
        ↓                                        ↓
   L3 중단위(소아크)                         스레드·아크 캡슐 갱신
        ↓                                        ↓
   L4 화별 개요                              ─┐
        ↓                                      │ 다음 회차의
   L5 회차 브리프 · 씬 · 비트                  │ 「진입 상태」로
        ↓                                      │ 되먹임
   L6 내용 잠금 · 문체 · 말투 · 공간           │
        ↓                                      │
   L7 본문 · 후편집 · 교차검증                 │
        ↓                                      │
   L8 승인 · 델타 · 상태 갱신 ─────────────────┘
```

**핵심 명제 세 개**

1. **본문 생성은 끝이 아니다.** 승인된 변화가 다음 화의 시작 상태로 넘어갈 때 한 회차가 끝난다.
2. **기억은 저장은 무손실, 컨텍스트는 의도적 손실.** 요약을 계속 이어 붙이지 않는다. 스냅샷은 **교체**하고 이력은 **델타**로 남긴다.
3. **아래에서 문제가 나면 위로 돌아간다.** 초고가 계속 망가지면 브리프를, 브리프가 계속 망가지면 개요를 고친다.

## 1. 출처 권위 순서 (Source authority)

충돌이 나면 위가 이긴다. **섞어서 절충하지 않는다.**

| 순위 | 출처 |
| --- | --- |
| 1 | 지금 이 요청에서의 사용자 지시 |
| 2 | 현행 설정집·전체 플롯 (정본) |
| 3 | 승인된 최신 상태 · 선례대장 · 승인 회차 본문 |
| 4 | 현재 회차 브리프 |
| 5 | 구고·문체 샘플 = **STYLE_ONLY** (사건을 정당화하지 않는다) |

**부속 규칙 두 개 — 사고가 실제로 났던 지점**

- **작중 인물의 설명은 정본이 아니다.** 「누가 누구에게」를 확인하고, 위장을 쓰는 인물이면 설정집이 이긴다. 인용할 때 화자·청자를 함께 적는다.
- **최근 회차 ≠ 인물의 규정.** 인물의 인지 방식·화법을 정한 것은 대개 **오래된 회차**다. 최근 것만 보면 인물이 바뀐다.

## 2. 설계 계층 (Level 0~8)

| 단계 | 산출물 | 핵심 질문 |
| --- | --- | --- |
| **L0** | 세계관·문체 바이블, **문서 레지스트리** | 무엇이 가능/불가능하며 어떤 문서가 우선하는가 |
| **L1** | 전체 플롯 | 어디서 시작해 어디로 끝나는가 |
| **L2** | 대단위 플롯(부·계절) | 이 구간의 주제와 **돌이킬 수 없는 변화**는 무엇인가 |
| **L3** | 중단위 플롯(월·소아크) | 어떤 소아크를 어디에 배치하는가 |
| **L4** | 화별 개요 | A/B/C, 변화, 말미 훅은 무엇인가 |
| **L5** | 회차 브리프·씬 구성·**비트 표** | 3~5개 씬이 어떤 인과로 이어지는가 |
| **L6** | 내용 잠금·문체 검색·**말투 카드·공간 시트** | 무엇을 쓸지 고정하고 어떤 예시를 쓰는가 |
| **L7** | 본문 생성·후편집·교차검증 | 설계·문체·상태·공개 순서를 지켰는가 |
| **L8** | 승인·델타·상태 갱신 | 무엇이 정사가 되었고 상태가 어떻게 변했는가 |

**소아크 단위**는 4~6화, 「도입 → 압박·오해 → 선택 → 결과 → 후처리」.

## 3. 승인 관문 (Gate)

| 관문 | 승인 대상 | 승인 전 상태 |
| --- | --- | --- |
| **0** | 세계관·전체 플롯·문체 바이블 **개정** | 변경 요청 |
| **A** | 대단위·중단위 플롯 | 설계 제안 |
| **B** | 화별 개요 | `DRAFT_OUTLINE` |
| **C** | 회차 브리프·씬 구성 | `DRAFT_BRIEF` |
| **D** | 후편집 본문 | `NONCANON_EXPERIMENT` |
| **E** | 회차 델타·새 상태 | 승인된 정사 |

- 상위 승인 전에 하위를 **대량으로** 쓰지 않는다.
- 본문 승인 전에 델타를 공식 상태에 반영하지 않는다.
- **표준 화**는 B·C를 소아크 단위로 묶어 한 번에 승인해도 된다. 파일은 분리하되 승인은 묶음.
- **중요 화**(소아크 전환·폭로·클라이맥스·중간점)는 B·C·D를 개별 승인한다. 중요 화 지정은 **Gate A에서** 미리 한다.
- 반려 사유는 코드로 기록한다 — `CANON` `CAUSALITY` `KNOWLEDGE` `STATE` `STYLE` `PACING` `HOOK` `FORMAT`.
  **같은 단계에서 두 번 반려되면 한 단계 위를 재검토한다.**

### Gate 0 — 정본을 바꿀 때

문서 레지스트리로 **영향 문서를 전부 열거**하고 각각을 `KEEP` / `REVISE` / `RETIRE` / `REBUILD`로 분류한 뒤에야 하위 문서를 손댄다.

## 4. 회차 루프 — 단계별 절차

### STEP 1. 정본 스윕 (브리프보다 **먼저**)

> 「정독한다」는 지켜지지 않는다. 그래서 도구로 강제한다.

승인 본문 전체를 키워드로 그렙해 **최초 등장**과 **최근 지면**을 뽑는다.

**최소 6종을 넣는다**

| # | 대상 |
| --- | --- |
| ① | 등장인물 **전원** (대사 없이 언급만 되는 인물도) |
| ② | 첫 등장·첫 밀착 인물 → **전 회차 목록(`--all`)** |
| ③ | 장소 — **건물이 아니라 「그 씬이 벌어질 방」** |
| ④ | 회고 대상 사건 |
| ⑤ | 소품·물건 |
| ⑥ | 되풀이되는 어휘·문형 (중복 방지) |

- **시점 인물이 바뀌는 회차**와 **주요 조연**은 반드시 `--all`로 돌려 **규정 문단**을 찾는다.
- 결과는 브리프 §0에 **지면 문장 그대로** 인용해 붙인다. 요약하면 또 놓친다.
- **붙이지 않은 브리프는 미완성이며 Gate C에 올리지 않는다.**

### STEP 2. 화별 개요 (L4) — Gate B

- A/B/C 세 줄기를 어디까지 움직일지 정한다.
- **A는 매 화 움직인다.** 일상 화에서는 작은 생활문제가 A다.
- B/C는 매 화 전진할 필요가 없다. 쉬는 줄기는 **마지막 진전 화 + 다음 예상 진전 구간**을 기록한다.
- 새 C(장기 떡밥)는 기존 떡밥의 **회수나 단계 상승과 맞교환**한다.
- 종료 상태가 이전 화와 **달라야 한다**. 변화 축: 정보 / 관계 / 성장·능력 / 행동 결과 / 감정 / 생활조건·자원 / 새 질문·선택.

### STEP 3. 회차 브리프 (L5) — Gate C

고정할 항목 7개:

1. 진입 상태 2. 중심인물의 즉각적 욕구 3. 방해 요소 4. 구체적 전환점
5. 정보 공개와 은폐 6. 종료 상태의 변화 7. 다음 화 동기

- **씬 분할 기준:** 목표·장소·시간·중심시점 가운데 **둘 이상**이 바뀔 때 나눈다. 개수 맞추려고 쪼개지 않는다.
- **공간 시트를 여기서 연다.** 방이 바뀌면 그 방에 있을 수 있는 사람이 바뀌고, 사람이 바뀌면 회차의 셈이 바뀐다.
- **★ 비트 표를 채운다** (§5).

### STEP 4. 내용 잠금 (L6)

- 쓸 사실·안 쓸 사실을 고정한다. **여기서 잠근 뒤에 문체 예시를 검색한다** (순서 역전 금지).
- **등장 인물 전원의 말투 카드를 실제로 열어** 요약을 넣는다.
  아는 인물일수록 안 보게 되고, 사고는 거기서 난다.
  최근 회차와 카드가 어긋나면 **어긋난 사실을 적고**, 상황 때문이면 상황이라 쓰고 기본값을 복원한다.
- 그 방의 세부 잠금 — 집기·동선·규정·**누가 들어올 수 있는가**.
- 전투/액션 회차는 **전장 구조(지형·엄폐물 내구·시야·거리)를 여기서 잠근다.** 잠그기 전에 쓴 산문은 재작성 대상이다.
- 문체 예시는 **장면 기능**으로 검색한다(2~4개, 짧게). 같은 플롯 내용으로 검색하면 구고 오염이 들어온다.

### STEP 5. 초고 (L7)

- **처음부터 목표 분량으로 쓴다.** 확장 패스는 복구 수단이지 공정이 아니다.
- 대사는 **누구에게 하는 말인지 먼저 정하고** 쓴다(화계는 청자를 따른다).
- 구고에서 가져오는 것은 **호흡·대사 행동·행동 순서·유머 기제·마감 기술**뿐. 사건은 절대 아니다.

### STEP 6. 기계 검사 (FAIL 하나라도 있으면 제출 금지)

| 검사 | 잡는 것 |
| --- | --- |
| **분량·문체 밴드** | 목표 자수 밴드, 시제 연속, 지시어 문두 밀도, 판단 종결 밀도 |
| **화계** | 존댓말/반말 드리프트, 서술문 내 호칭 |
| **번역투** | 번역투·문어체(에세이 어투) 침투 |
| **정합·중복** | 인물 감시목록, 시간 지시어, 봉인 어휘, **승인 회차와의 축자 중복** |
| **금칙어 그렙** | 구판 용어 + 이 회차 잠금이 추가한 금칙 |

> 임계값은 **승인본 전수 실측**으로 잡는다 — 「지금까지의 문체」가 기준선이다.
> 그래야 WARN이 노이즈가 아니라 실제 드리프트가 된다.
> **밴드는 상한이지 목표가 아니다.** 인물 고유의 문형을 깎아 밴드를 맞추면 인물이 무너진다.

### STEP 7. 교차검증 (Gate D 이전)

**초고 작성과 분리된 패스**로 대조한다.

- 인물별 지식·오해·거짓말 (비대칭 유지)
- 부상·위치·장비·자원·도시 상태
- 시기별 등장·무장·공개 순서의 확정선
- 현행 용어와 구판 금칙어
- 목표 분량·씬 수·말미 훅

보고서는 `PASS` / `WARN` / `FAIL`. **`FAIL`이 하나라도 있으면 Gate D에 올리지 않는다.**
어휘 스캔만으로는 부족하다 — **의미 층위의 구고 오염 검토**를 따로 한다.

### STEP 8. 승인 → 델타 → 상태 (L8, Gate E)

**6~8은 하나의 트랜잭션이다.** 반려·실험 원고는 공식 기억을 절대 바꾸지 않는다.

1. 승인 확인
2. 델타 작성 — **이 회차가 바꾼 것만**
3. 델타를 적용해 **새 스냅샷으로 교체**
4. 떡밥 트래커 갱신 — 해결된 것은 활성에서 이력으로
5. 이전 스냅샷·전문·브리프·델타는 **보관**(실시간 컨텍스트에서는 제외)
6. 8~12화마다 또는 아크 전환점에서 **아크 캡슐**

## 5. 비트 표 — 분량 미달과 중언부언의 근본 대책

**분량 미달과 중언부언은 같은 원인이다.** 재료가 모자라면 이미 쓴 것을 다른 말로 한 번 더 한다.

**목표 자수 ÷ 비트당 자수 = 필요 비트 수. 비트가 모자라면 Gate C를 통과해도 초고에 들어가지 않는다.**

| 비트다 | 비트가 아니다 |
| --- | --- |
| **새 사실** (사물·사람·시각·수치) | 이미 내린 판단의 재진술 |
| **새 동작** (절차의 다음 단계) | 같은 문형의 다른 목적어 |
| **새 판단** (인물이 **처음** 내리는 결론) | 앞 씬 요약 |
| **대사 교환 한 덩이** | 분위기 묘사만 |

- **자문:** 그 문단을 지웠을 때 **독자가 모르게 되는 사실이 있는가.** 없으면 분량이지 서술이 아니다.
- **사전에 세우면 비트, 사후에 붙이면 분량.**
- **마감 씬부터 채운다.** 앞 씬은 상황이 밀어 주지만 마감 씬은 재료를 따로 세워 두지 않으면 빈다.
- 문단 수는 지표로 쓰지 않는다(편차가 큼). **씬당 자수와 비트 수**만 쓴다.

## 6. 기억 6층

| 층 | 내용 | 갱신 |
| --- | --- | --- |
| **1. 불변 정본** | 세계 규칙·인물 기초·고정 연표·기술·공개 순서 | 사용자가 명시적으로 바꿀 때만 (버전·출처 보존) |
| **2. 현재 스냅샷** | 최종 승인 회차, 작중 날짜, 위치, 신체·부상, 감정·관계, **누가 무엇을 아는가**, 소지품·장비, 공적 상황 | 승인마다 **교체** |
| **3. 활성 스레드** | ID, 질문·약속, 도입 화, **마지막 진전 화**, 보유자, 긴급도, 예상 구간, 허용 해석 | 회차마다 |
| **4. 회차 델타** | 변한 것만. 현재를 재구성할 수 있는 감사 추적 | 회차마다 |
| **5. 아크 캡슐** | 초기 상태, 돌이킬 수 없는 사건, 관계·지식 이동, 자원, 떡밥, 이월 스레드, 감정 압력 | 8~12화 |
| **6. 전체 아카이브** | 승인 전문·폐기안·원본 문서·구 스냅샷 | 컨텍스트 밖 보관 |

**델타 작성 규칙**

- 해석이 아니라 **사실**을 적는다.
- 신체 / 감정 / 관계 / 정보 / 물자 / 공적 / 떡밥 / 스레드를 **갈라서** 적는다.
- 모든 지속 변화에 **출처 회차·씬**을 붙인다.
- **지식 비대칭을 보존한다.** 한 명만 아는데 「가족이 안다」로 적으면 틀린 것이다.
- 새 거짓말·위장은 **진실과 별도 칸**에 적는다.
- 「악화됨」이 아니라 **증상 강도와 지속**을 적는다.
- 파손 / 사용불가 / 분실 / 소모 / 수리 / 개조를 구분한다.

**압축 감사 — 10화마다**

1. 마지막 감사 스냅샷 + 델타로 현재를 **재구성**해 유지 중인 스냅샷과 대조
2. 아크 캡슐 체인과도 대조
3. 연표·나이·이동시간·부상·소지품·지식 비대칭·관계·활성 스레드 점검
4. **요약에만 있고 델타·정본에는 없는 사실**을 찾아낸다 (= 환각이 정착한 자리)
5. 해결된 스레드 정리, 반복 디테일의 정본 승격은 **승인 후에만**

전수 대조는 **레트콘 · 계절 경계 · 체인 감사에서 불일치가 났을 때**만.
충돌이 안 풀리면 **양쪽 출처를 제시하고 사용자에게 묻는다. 조용히 고르지 않는다.**

## 7. 컨텍스트 조립

**넣는 순서**

1. 관련 정본 발췌 2. 최신 스냅샷 3. 활성 아크 캡슐 4. 이 회차 관련 활성 스레드
5. 최근 2~3화 델타 6. 승인된 브리프 7. 장면에 맞는 말투·문체 카드와 짧은 예문

**조립 절차:** 승인 브리프에서 인물·장소·장비·떡밥 **ID를 추출**해, 그 ID의 카드와 상태 필드만 넣는다.

**한도 초과 시 빼는 순서:** 해결된 이력 → 무관한 정본 → 문체 예문 → 오래된 델타.
*현재 상태를 압축하는 것은 마지막 수단이다.*

**떡밥 트래커의 최종 진실은 본문 생성 컨텍스트에 넣지 않는다.**
생성에는 **현재 허용 공개치와 금지 공개치**만 전달한다.

## 8. 회차 산출물 세트

한 회차가 끝나면 **고정된 산출물 묶음**이 남는다. 하나라도 빠지면 다음 회차의 입력이 깨진다.

| # | 산출물 |
| --- | --- |
| 1 | **승인 본문** (`…_v1.0_GateD승인.md`) — 이전 초고는 `_superseded/`로 |
| 2 | Gate D 검증서 |
| 3 | 회차 델타 |
| 4 | 다음 상태 스냅샷 |
| 5 | 다음 떡밥 트래커 스냅샷 |
| 6 | **등장 대장** — 「오래 안 나온 인물」을 잡아 주는 것이 이것이다 |
| 7 | Gate E 상태반영서 |
| 8 | 프로젝트 상태 문서 갱신 → 스킬 사본 동기화 |
| 9 | 리뷰 페이지 재빌드·재발행 (고정 URL) |

**폴더 규약:** `NN_EPxxx/` (작업 중) → 승인되면 `NN_EPxxx_승인완료/`로 이름만 바꾼다.
**빌더가 폴더명으로 「작업 중 / 승인」을 판정**하므로 별도 조작이 필요 없다.

**승인 요청은 사용자가 읽는 매체에 먼저 올린다.**
브리프·L6는 작성 직후, 초고는 검사 통과 직후에 발행한다. 터미널 출력만 놓고 승인을 요청하지 않는다.

## 9. 규칙이 쌓이는 경로 — 이 파이프라인의 자기 수리 장치

사용자 지적이 나왔을 때 **세 군데에 동시에** 꽂는다.

| 성격 | 어디에 |
| --- | --- |
| **행동 규칙** (앞으로 이렇게 써라) | 상시 가드 문서 + 세션 인계서 |
| **지면 사실** (이미 정해진 것) | **선례대장** — 화계, 구조, 동선, 약속의 문구 |
| **기계로 잡히는 것** | 검사기에 지표·임계값 추가 → 승인본 전수로 재보정 |

**두 가지 태도가 이 파이프라인을 유지한다.**

1. **지적은 국소가 아니라 계통으로 본다.** 한 곳이 틀렸으면 승인 회차 전체를 같은 패턴으로 쓸어 본다.
   (실제 사례: 한 화에서 발견된 화계 드리프트가 13개 회차 44줄이었다.)
2. **「정독한다」로 지켜지지 않는 규칙은 도구로 강제한다.** 규칙을 강조하지 말고 스크립트로 만든다.

## 10. 새 작품에 이식할 때 — 갈아 끼우는 슬롯

구조는 그대로 두고 아래만 채운다.

| 슬롯 | 정하는 것 | 블랙 타이탄의 값(예시) |
| --- | --- | --- |
| **반복 루틴** | 이 작품이 매 화 돌아오는 생활의 중심점 | 학교 → 동네 → 수리점·가족 → 징후 → 전투 → 후처리 |
| **대단위 축** | L2를 무엇으로 나누는가 | 계절(봄·여름·가을) |
| **회차 규격** | 목표 자수 · 씬 수 · 씬당 자수 | 5,500자 · 3~5씬 · 씬당 약 966자 |
| **비트 밀도** | 비트당 자수 → 필요 비트 수 | 100자 → 55비트 |
| **문체 밴드** | 승인본 실측으로 잡은 지표와 상한 | 지시어 문두 / 판단 종결 |
| **화계 표** | 누가 누구에게 어떤 말투인가 | 인물×청자 표 |
| **금칙어** | 구판 용어·작가용 표기·봉인 어휘 | 구판 인명·기관명, 개체 분류 표기 |
| **공간 시트** | 장소별 블록아웃 — 방·동선·규정 | LOC-00 ~ LOC-07 |
| **말투 카드** | 인물별 리듬·관심사·감정 우회·호칭·**금지 표현** | 계절별 카드 |
| **적/장애 시트** | ① 원형 ② **치명(수단·조건·대가)** ③ 목적(표층·중층·심층) | 괴수 시트 |
| **감시목록** | 실제로 틀렸던 항목만 넣는 경고 목록 | 반 배치·용어 오용 |

**적/장애 시트 3원칙은 장르 불문으로 쓸 만하다.**
특히 ②의 **「대가」가 비면 갈등이 안 무섭다.** 이겨도 뭔가는 치러야 한다.

## 11. 최소 구성 — 이 중 무엇을 먼저 만드나

새 작품에서 처음부터 전부 세울 수는 없다. 순서는 이렇다.

| 순 | 만드는 것 | 없으면 생기는 일 |
| --- | --- | --- |
| 1 | **출처 권위 순서 + 문서 레지스트리** | 어느 문서가 이기는지 몰라 매번 재논쟁 |
| 2 | **상태 스냅샷 + 델타 양식** | 인물 상태가 회차마다 초기화 |
| 3 | **승인 관문 A~E** | 실험안이 조용히 정사가 됨 |
| 4 | **정본 스윕 도구** | 지면에 답이 있는데 틀림 |
| 5 | **회차 브리프 + 비트 표** | 분량 미달 → 확장 패스 → 중언부언 |
| 6 | **말투 카드 + 화계 검사기** | 인물이 서로 구분되지 않음 |
| 7 | **선례대장 + 상시 가드** | 같은 지적을 반복해서 받음 |
| 8 | 문체 밴드 검사기 | 문형 복제가 누적 |
| 9 | 아크 캡슐 + 10화 압축 감사 | 후반부에 장기 인과가 무너짐 |

**1~3이 없으면 나머지는 의미가 없다.** 4~7이 실제 사고를 가장 많이 막는다.

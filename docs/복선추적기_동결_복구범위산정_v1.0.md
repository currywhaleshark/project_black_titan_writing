## 5. 복구 선택지 세 가지

### A안 — 정직하게 표시만 (0.5시간 · 기계적)

34개 파일에 동결 사실을 명시한다.

```yaml

payload_frozen: true
frozen_note: "EP068~101 구간 미반영. 근거는 각 회차 회차델타 foreshadow 블록."
```

> **주의: 스탬프만 068~101로 고치는 것은 금지.** 내용이 EP067인 파일에
> EP101 도장을 찍으면 **동결이 정상으로 위장된다.** 2026-08-21에 주석만
> 고친 것이 정확히 그 실수였다.

- 얻는 것: `bt_doctor` 검사 2가 오탐 없이 통과. 다음 사람이 안 속는다
- 못 얻는 것: 조회 불가는 그대로

### B안 — 현재 상태만 보강 ★권장 (3~5세션 · 사용자 판단 필요)

**34개 과거 파일은 건드리지 않는다.** 대신 SNAP-142의 `active:`에
EP068~101 신규 복선을 구조화 항목으로 승격한다.

- 입력: 33개 회차델타 `foreshadow:` 블록 (202건)
- 작업: 이미 표현된 것 걸러내고 → 신규 약 93건을 정식 엔트리로 작성
- 우선순위: **S11(EP77~92) 16화가 0건이므로 여기부터**

근거: 과거 스냅샷을 여는 일은 드물다("EP80 시점 상태가 뭐였나"). 반면
현재 상태는 **집필 때마다** 읽는다. 같은 노력으로 얻는 값이 가장 크다.

### C안 — 전량 재구성 (10세션 이상)

SNAP-067에서 출발해 델타 34개를 순차 적용, 068~101을 다시 만든다.
가장 정확하지만 비용이 B안의 3배 이상이고, **B안을 끝내야 C안의 각
중간 상태가 정의된다.** 단독으로 먼저 할 일이 아니다.

## 6. 왜 스크립트로 못 돌리는가

델타에서 기계적으로 뽑히는 것:

| 필드 | 자동 | 근거 |
| --- | --- | --- |
| `planted_at` | ○ | 델타의 `(68)` 표기 |
| `surface_reading` | ○ | 항목 본문 |
| `next_window` | △ | `→ EP69` 화살표가 있을 때만 |
| `last_progressed` | ○ | 마지막 언급 회차 |
| `name` · `line` · `secret_layer` | ✗ | 명명·계통 배정은 작가 판단 |
| **`allowed_reveal_now`** | **✗** | **지금 어디까지 써도 되는지** |
| **`prohibited_reveal_now`** | **✗** | **무엇이 봉인인지** |

마지막 두 필드가 이 추적기의 실사용 목적 전부다. 이걸 추정으로 채우면
**틀린 봉인 정보를 정본으로 만드는 것**이라 동결보다 나쁘다.

→ **스크립트는 델타에서 초안을 뽑아 나열하는 데까지. 판정은 사용자.**

가는 조립부**라 복선 밀도 자체가 높은데, EP101~102가 재구축 지점이라
바로 앞 여덟 회차가 통째로 새어 나갔다.

## 1. 목적

- AI와 사람이 함께 장편 웹소설을 안정적으로 제작하는 표준 절차를 정한다.
- 즉흥적으로 본문부터 쓰지 않고 상위 설계에서 하위 설계로 내려간다.
- 설정 붕괴, 플롯 누락, 인물 상태 초기화, 문체 이탈을 줄인다.
- 실험안과 승인된 정사를 구분해 잘못된 기억 누적을 막는다.

## 2. 핵심 원칙

매 화 거대한 사건보다 독자가 체감할 수 있는 변화가 하나 이상 필요하다.

- 정보
- 관계
- 성장·능력
- 전투·행동 결과
- 감정
- 생활조건·자원
- 새로운 질문이나 선택

분위기만 있고 아무 상태도 달라지지 않는 화를 피한다. 변화를 회차 종료 상태에
기록한다.

## 3. A/B/C 스토리 구조

| 구분 | 기능 | 예시 |
| --- | --- | --- |
| A | 현재 회차나 소아크의 전면 사건 | 괴수, 고장 난 물건, 친구와의 약속 |
| B | 여러 화에 걸쳐 누적되는 갈등 | 혜정의 의심, 단아의 피로, 가족의 거짓말 |
| C | 장기 떡밥과 후반부 원인 | 도현서, 루시, 고명준의 과거, 외계 신경기원 |

운용:

- A는 매 화 움직인다. 일상 화에서는 작은 생활문제가 A가 될 수 있다.
- B와 C는 매 화 모두 전진시킬 필요가 없다.
- 쉬는 B/C는 마지막 진전 화와 다음 예상 진전 구간을 기록한다.
- B→A, C→B 이동은 매 화가 아니라 소아크 전환이나 폭로 시점에 일어난다.
- 새로운 C는 기존 떡밥의 회수나 단계 상승과 맞교환한다.
- 한 장면에 A/B/C를 모두 억지로 넣지 않는다.

## 4. 작품의 반복 루틴

Project Black Titan은 학교·가족·도시를 지키는 생활형 거대로봇 드라마다.

학교 → 구래동 → 수리점·가족 → 징후 → 괴수·전투 → 후처리 → 학교

- 모든 화에 학교를 넣지 않는다.
- 전투 없는 여러 화도 허용한다.
- 학교와 구래동은 반복해서 돌아오는 생활의 중심점이다.
- 전투 후 부상, 거짓말, 결석, 정비, 비용, 부품, 도시 피해를 다룬다.
- 일상이 충분히 축적되어야 파괴의 위협이 작동한다.

## 5. 설계 계층

| 단계 | 산출물 | 핵심 질문 |
| --- | --- | --- |
| Level 0 | 세계관·문체 바이블, 문서 레지스트리 | 무엇이 가능하고 불가능하며 어떤 문서가 우선하는가? |
| Level 1 | 전체 플롯 | 어디에서 시작해 어디로 끝나는가? |
| Level 2 | 계절 플롯 | 계절 주제와 돌이킬 수 없는 변화는 무엇인가? |
| Level 3 | 월별 플롯 | 어떤 소아크를 배치하는가? |
| Level 4 | 화별 개요 | A/B/C, 변화, 말미 훅은 무엇인가? |
| Level 5 | 회차 브리프·씬 구성 | 3~5개 씬이 어떤 인과로 연결되는가? |
| Level 6 | 내용 잠금·문체 검색 | 무엇을 쓸지 고정하고 어떤 문체 예시를 쓰는가? |
| Level 7 | 본문 생성·후편집·교차검증 | 설계·문체·상태·공개 순서를 지키는가? |
| Level 8 | 승인·델타·상태 갱신 | 무엇이 정사가 되었고 상태가 어떻게 변했는가? |

하위 단계에서 문제가 생기면 원인이 있는 상위 단계로 돌아간다.

## 6. 계절·월·소아크 단위

계절마다 주제, 적의 목적, 성장단계, 대표 클라이맥스를 정한다. 구체적인
서사 사실과 월별 배치는 이 절차 문서에 중복 기록하지 않고 최신 전체 플롯과
승인된 계절·월별 플롯을 참조한다.

4~6화를 하나의 소아크로 보고 도입→압박·오해→선택→결과→후처리를 배치한다.

## 7. 화와 씬의 구조

한 화는 약 5,500자, 3~5개 씬을 기준으로 한다.

먼저 고정할 항목:

1. 진입 상태
2. 중심인물의 즉각적인 욕구
3. 방해 요소
4. 구체적인 전환점
5. 정보 공개와 은폐
6. 종료 상태의 변화
7. 다음 화 동기

씬 수를 맞추려고 장면을 쪼개지 않는다. 목표·장소·시간·중심시점 가운데 둘
이상이 바뀔 때 씬을 나눈다.

## 8. 회차 엔딩 원칙

다음 화를 읽을 이유를 남긴다.

- 질문
- 새로운 정보
- 감정의 잔향
- 인물·위협의 등장
- 선택 또는 행동
- 사물·신체 이상·멈춘 동작

억지 클리프행어를 피하고 감정 엔딩도 적극 활용한다. 마지막 문장은 앞 문단의
의미를 바꾸되 주제를 직접 해설하지 않는다.

> **「뭔가 확장패스 사용감이 나빠졌는데 / 비슷한 묘사가 중언부언되는 느낌」**

### ★★★★★★ 비트 표 — 확장 패스를 안 돌기 위한 사전 조치 (2026-08-24 신설)

#### 왜 생겼는가

§8-2의 「확장 패스는 문형을 복제하지 않는다」는 **증상을 막는 규칙**이다.
**원인은 따로 있다** — 사용자 지적:

> **「확장패스에 지나치게 의존하지 않으려면 브리프 단계에서 사건을 좀 더
> 촘촘히 정해놓으면 좋지 않을까」**

**★★★★★ 분량 미달과 중언부언은 같은 원인이다.**
재료가 모자라니 쓸 것이 떨어지고, 떨어지면 **이미 쓴 것을 다른 말로 한 번 더**
한다. 확장 패스는 그 부족을 사후에 메우려다 문형을 복제한다.

#### ★★★★ 규칙 — 브리프 §Beat sheet

**목표 자수 ÷ 100 = 필요 비트 수.**
**비트가 모자라면 Gate C를 통과해도 초고에 들어가지 않는다.**

| 비트다 | 비트가 아니다 |
| --- | --- |
| **새 사실**(사물 · 사람 · 시각 · 수치) | **이미 내린 판단의 재진술** |
| **새 동작**(절차의 다음 단계) | 같은 문형의 다른 목적어 |
| **새 판단**(인물이 **처음** 내리는 결론) | 앞 씬 요약 |
| **대사 교환 한 덩이** | 분위기 묘사만 |

**★★★ §8-2의 자문과 같은 것이다** — 빼면 독자가 모르게 되는 것이 있는가.
**사전에 세우면 비트고, 사후에 붙이면 분량이다.**

#### ★★★★★★ 세지 않으면 비트 표가 없는 것이다 (2026-08-26 신설)

> **「내 생각에 이번에 비트가 모자랐던것같다 / 애초에 기획 단계에서 한 화에 쓸 재료가

## 9. 승인 관문

| 관문 | 승인 대상 | 승인 전 상태 |
| --- | --- | --- |
| 0 | 세계관·전체 플롯·문체 바이블 개정 | 변경 요청 |
| A | 계절·월별 플롯 | 설계 제안 |
| B | 화별 개요 | `DRAFT_OUTLINE` |
| C | 회차 브리프·씬 구성 | `DRAFT_BRIEF` |
| D | 후편집 본문 | `NONCANON_EXPERIMENT` |
| E | 회차 델타와 새 상태 | 승인된 정사 |

- 상위 설계 승인 전에 하위 단계를 대량 작성하지 않는다.
- 본문 승인 전에 델타를 공식 상태에 적용하지 않는다.
- 승인 후 사건을 바꾸면 델타와 상태를 다시 계산한다.
- 표준 화는 소아크 단위로 Gate B·C를 묶어 검토할 수 있다. 개요와 브리프
  파일은 분리하되 한 번의 승인 묶음으로 처리한다.
- 소아크 전환, 폭로, 계절 클라이맥스, 중간점 등 중요 화는 B·C·D를 개별
  승인한다. 중요 화 지정은 Gate A에서 한다.

### Gate D 이전 교차검증

초안 작성 역할과 분리된 검증 패스로 다음을 대조한다.

- 인물별 지식·오해·거짓말
- 부상, 위치, 장비, 자원, 도시 상태
- 시기별 무장·등장·공개 순서의 확정선
- 현행 용어와 구판 금칙어
- 목표 분량·씬 수·말미 훅

검증 보고서는 `PASS`, `WARN`, `FAIL`로 나눈다. `FAIL`이 하나라도 있으면
Gate D에 제출하지 않는다.

### 반려와 재작업

반려 사유는 `CANON`, `CAUSALITY`, `KNOWLEDGE`, `STATE`, `STYLE`,
`PACING`, `HOOK`, `FORMAT` 가운데 하나 이상으로 기록한다. 같은 단계에서
두 번 반려되면 한 단계 위 설계를 재검토한다.

## 10. 장기기억 갱신

Level 8:

1. 승인 본문에서 변한 사실만 회차 델타로 추출한다.
2. 신체, 감정, 관계, 지식, 거짓말, 위치, 장비, 자원, 도시 상태를 구분한다.
3. 기존 현재상태에 델타를 적용해 새 스냅샷으로 교체한다.
4. 해결된 떡밥을 활성 목록에서 이력으로 보낸다.
5. 전문과 이전 스냅샷은 보관하되 실시간 컨텍스트에서는 뺀다.
6. 8~12화마다 또는 소아크 전환점에서 아크 캡슐을 만든다.
7. 10화마다 최신 스냅샷을 델타·캡슐 체인과 대조한다. 원문 전수 대조는
   레트콘과 계절 경계에서 수행한다.

실시간 컨텍스트:

- 관련 현행 설정
- 최신 상태 스냅샷
- 활성 A/B/C와 미해결 떡밥
- 최근 2~3화 델타
- 승인된 회차 브리프
- 필요한 문체 카드와 짧은 예문

컨텍스트 조립:

1. 승인된 브리프에서 등장 인물·장소·장비·활성 떡밥 ID를 추출한다.
2. 해당 ID의 카드와 상태 필드만 넣는다.
3. 한도를 넘으면 문체 예문, 오래된 델타, 비관련 설정 순으로 뺀다.
4. 떡밥 트래커의 최종 진실은 플롯·검증 단계에서 사용한다. 본문 생성에는
   현재 허용 공개치와 금지 공개치만 전달한다.

## 11. AI와 사람의 역할

사람:

- 작품 방향과 정사 결정
- 승인 관문 판단
- 핵심 선택과 감정선 최종 판단
- AI 제안의 채택·폐기·수정

AI:

- 상위 설계를 하위 설계로 구체화
- 빠진 인과, 상태 변화, 떡밥, 훅 후보 탐색
- 승인 브리프에 따른 본문 작성
- 문체 적용과 구판 오염 검사
- 회차 델타와 상태 스냅샷 작성

AI 제안은 사용자 승인 없이 정사로 승격하지 않는다.

## 12. 체크리스트

기획:

- 계절·월·소아크 기능에 맞는가?
- A가 명확한가?
- B 또는 C가 필요한 속도로 움직이는가?
- 종료 상태가 이전 화와 다른가?
- 지키려는 학교·가족·도시 생활이 구체적인가?
- 전투가 적의 목적과 성장단계를 반영하는가?
- 말미에 다음 화 동기가 있는가?

본문:

- 내용 잠금 뒤 문체 예문을 검색했는가?
- 신설정만이 사건과 사실을 결정하는가?
- 구판에서는 문장 호흡과 장면 기능만 가져왔는가?
- 인물별 말투가 구분되는가?
- 행동 뒤에 같은 감정을 반복 설명하지 않는가?
- **★ 브리프 비트 표를 채웠는가?**(§8-2 · **재료 확인용** · 마감 씬부터)
- **★★★ 씬을 끝낼 때마다 자수를 쟀는가?**(§8-2 · **80% 미만이면 그 씬에서 보정**)
- **확장 패스가 붙인 문단을 지웠을 때 사라지는 사실이 있는가?**(§8-2)
- **`check_draft.py`의 `deictic`·`closer`가 밴드 안인가?**(29.4 / 67.5)
- **`check_continuity.py` [4] 축자 중복이 인장 외에 없는가?**
- 전투 위치와 인과를 따라갈 수 있는가?

기억:

- 실험 원고와 승인 원고를 구분했는가?
- 회차 델타와 새 상태 스냅샷을 만들었는가?
- 인물별 지식과 오해를 따로 갱신했는가?
- 활성 떡밥의 마지막 진전 화를 갱신했는가?
- 오래 쉬는 B/C에 다음 예상 진전 구간이 있는가?

운영:

- 문서 레지스트리의 버전·상태·우선순위가 최신인가?
- 중요 화와 표준 화의 승인 방식이 구분되었는가?
- Gate D 전 교차검증의 `FAIL`이 모두 해소되었는가?
- 반려 사유와 상위 단계 회귀 여부를 기록했는가?

본문 생성은 파이프라인의 끝이 아니다. 승인된 변화가 다음 화의 시작 상태로
넘어갈 때 한 회차가 완성된다.

## 13. 문서 변경과 레트콘

- 파일명, 내부 표제, 문서 레지스트리의 버전을 함께 갱신한다.
- Gate 0 변경 요청에는 변경 전·후 사실, 영향받는 개요·브리프·델타·
  스냅샷·떡밥을 나열한다.
- 승인되면 영향 산출물을 `KEEP`, `REVISE`, `RETIRE`, `REBUILD`로 분류한다.
- 델타 이력은 덮어쓰지 않는다. 레트콘 기록을 추가하고 마지막 유효
  스냅샷부터 새 상태를 재구축한다.
- 절차 문서에는 서사 사실을 중복 보유하지 않는다. 현행 설정·전체 플롯의
  정확한 문서 ID와 절만 참조한다.
